# Трендвотчер по фитнех публикациям

На текущий момент прототип имеет функционал нескольких режимов сбора данных, очистки от шума и дублей, а также оценивания сигналов, создания самого отчета и приложенных к нему интерпретируемых метрик

Основана на заданных правилах с возможностью обогащения сигналов через LLM.

В качестве интерфейса используется **streamlit**, также возможен кодовый запуск
  

## Запуск


```bash

cd ~/Desktop/fintech-trendwatcher
python -m pip install -r requirements.txt
python scripts/run_pipeline.py
streamlit run app.py

```


## Какую проблему решает

Финансовые аналитики и команды ежедневно сталкиваются с большим числом информации, поэтому для них становится затруднительным решить, какая из них действительно может принести пользу, а какая не является столь значимой.

Это потребляет большое число ресурсов и времени и затрудняет работу. Чтобы решить эту проблему, требуется сервис, который смог бы определять
- методы оперативно собирать актуальную информацию
- какие публикации действительно важны
- какие являются дубликатами
- почему конкретная информация попала в итоговый отчет
- показывать интерпретируемые метрики

# Шаги

## Шаг 1. Сбор данных

Поддерживаются три варианта:
- Демо набор: детерминированные варианты
- CSV: пользователь может загрузить файл с определенными колонками с указанием нужной ему информации
- RSS: источники в реальном времени
  
RSS-источники:
- Банк России 
- РБК - новости
- Finextra
- TechCrunch Fintech
- The Paypers
- PYMNTS
- Stripe Blog

## Шаг 2. Нормализация

Данные приводятся к единой схеме, а также добавляются технические поля:

```text
canonical_url
domain
normalized_title
dedup_text
source_quality (на основе заданных параметров)
content_length
```

## Шаг 3. Фильтрация шума

Фильтрация также реализована на основе словарей и правил через подсчет слов и вхождений, например, если публикация ЦБ РФ, но имеет признаки нумизматики, она фильтруется как нерелевантная для банковских аналитиков

Статья получает параметры:

```text
is_candidate
noise_reason
allow_hits
deny_hits
relevance
candidate_score
detected_category
```

## Шаг 4. Определение категории сигнала

Категория определяется по ключевым словам, текущий список категорий:

```text
payments: платежи
banking_product: различные виды банковских продуктов
UX: приложения, лояльность, пользователи
partnership: партнерство и экосистема
regulation: регуляторы и закон
fraud_risk: мошенничество и антифрод
market_signal: информация о рынке
```

## Шаг 5. Дедупликация

На выбор пользователя есть 2 варианта: Fuzzy и TF-IDF режимы

### Fuzzy

Используется конкатенация и последующее строковое сходство через **SequenceMatcher**, объединяются при совпадающем URL или степени похожести

## TF-IDF

Используется TfidfVectorizer + cosine_similarity, на основе них определяются и фильтруются похожие тексты. ngram_range = $(1;2)$

## Шаг 6. Создание сигналов

После дедупликации каждая группа превращается в один сигнал. Он содержит:

```text
headline
category, tags
published_at, date_label, freshness_label
sources
summary,
why_now,
suggested_action
score_explanation
```

Исключения обрабатываются (например, отсутствие полного текста). 

Score считается по формуле:
$$
score = 0.30 * relevance + 0.20 * source\_quality + 0.20 * novelty + 0.15 * impact + 0.15 * evidence\_count

$$

relevance - среднее релевантности группы
source_quality - максимум качества источника в группе
evidence_count - число уникальных независимых url в группе
novelty - считается по ключевым словам + формуле, учитывает свежесть
impact - считается по ключевым словам, учитывает категории и параметры


## Шаг 7. Обогащение через LLM

Если эта опция отмечена и указан ключ, то после, с помощью промптов с указанным форматом дополняются результаты: улучшается устойчивость и репрезентативность

## Шаг 8. Генерация отчета

Генерируется и сохраняется отчет из лучших сигналов, а также создаются рекомендованные действия на основе уверенности и типа сигналов, что помогает аналитику решить, как стоит действовать.

Результаты сохраняются в:

- `data/articles.csv`: все нормализованные публикации
- `data/candidates.csv`: публикации, прошедшие фильтр
- `data/rejected.csv`: отфильтрованные +причины
- `data/signals.json`: итоговые карточки
- `data/digest.md`: финальный отчет



## Объяснимость

Проект не только показывает итоговый результат, но и причины решений:
- причины, почему статья стала кандидатом
- почему она отфильтрована
- ключевые слова, категории
- какие публикации были объединены
- как считается score
- что попало в финальный отчет
